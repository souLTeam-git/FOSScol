# Плагины FOSScol

Плагин FOSScol — это обычный Python-файл, который получает одну строку
результата и может изменить её значения, добавить новые колонки или удалить
лишние. Плагины подключаются без правок ядра и работают как для встроенных,
так и для пользовательских файлов.

---

## 1. Как устроены плагины и куда их класть

### Папка `plugins/`

Все плагины лежат в папке `plugins/` рядом с `main.py`:

```text
FOSScol/
├── main.py
├── plugins/
│   └── my_plugin.py
└── ...
```

- Любой файл `*.py` в `plugins/` автоматически проверяется при запуске
  приложения.
- Кнопка **«Обновить список»** на вкладке **«Плагины и Экспорт»** заново
  сканирует папку.
- Кнопка **«Установить плагин (.py)...»** копирует выбранный файл в `plugins/`.
- Кнопка **«Удалить плагин»** удаляет файл, но настройки плагина остаются
  в JSON кампании. Если файл вернуть, настройки снова начнут применяться.
- Файлы, имя которых начинается с `_`, при сканировании пропускаются.
- В одном файле объявляется класс-наследник `BasePlugin`. Если файл содержит
  несколько таких классов, будут загружены все.
- `id` плагина должен быть уникальным. При совпадении `id` один из файлов
  будет пропущен с предупреждением.
- Ошибка импорта одного файла не мешает загрузке остальных плагинов и не
  останавливает приложение.

### Где хранятся настройки

Настройки каждого плагина хранятся в JSON кампании:

```json
{
  "plugins": {
    "my_plugin": {
      "enabled": true,
      "prefix": "NEW: "
    },
    "list_separator": {
      "enabled": true,
      "separator": ", "
    }
  }
}
```

При открытии кампании интерфейс объединяет значения из JSON со значениями
`default_config()` и добавляет недостающие `default` из `config_schema()`.
Сохранённые значения имеют приоритет. При сохранении кампании итоговый конфиг
записывается обратно в JSON.

Плагин запускается только если одновременно выполнены два условия:

1. в кампании включён `enabled: true`;
2. файл плагина установлен в `plugins/`.

Если файл удалён, кампания продолжает работать, а плагин просто пропускается.

### Порядок выполнения

У каждого плагина есть атрибут `order`. Чем меньше значение, тем раньше
выполняется плагин. При одинаковом `order` плагины сортируются по `id`.
Сортировка стабильная и используется как в цепочке обработки, так и в списке
плагинов интерфейса.

Если плагину нужно обработать данные раньше или позже, задайте свой `order`,
например `order = 70` или `order = 150`.

## 2. Полный контракт `BasePlugin`

Минимальный плагин выглядит так:

```python
from __future__ import annotations

from typing import Any

from core.plugins.base import BasePlugin


class MyPlugin(BasePlugin):
    id = "my_plugin"
    name = "Мой плагин"
    description = "Короткое описание"
    order = 100

    def default_config(self) -> dict[str, Any]:
        return {"enabled": False}

    def config_schema(self) -> list[dict[str, Any]]:
        return []

    def process_row(
        self,
        row: dict[str, Any],
        config: dict[str, Any],
        campaign: dict[str, Any],
    ) -> dict[str, Any]:
        return row
```

### Атрибуты класса

| Атрибут | Тип | Назначение |
|---|---|---|
| `id` | `str` | Уникальный идентификатор. Используется как ключ в `campaign["plugins"]`. Рекомендуется `snake_case`, например `price_markup`. |
| `name` | `str` | Название плагина в интерфейсе. |
| `description` | `str` | Краткое описание для карточки плагина. |
| `order` | `int` | Приоритет выполнения. По умолчанию `100`. Меньше — раньше. |

Если изменить `id` уже используемого плагина, кампания будет считать его
новым плагином: старые настройки останутся под старым `id`.

### Методы

#### `default_config() -> dict[str, Any]`

Возвращает настройки для новой кампании. Рекомендуется всегда включать
`"enabled": False`:

```python
def default_config(self) -> dict[str, Any]:
    return {
        "enabled": False,
        "prefix": "",
    }
```

`enabled` — стандартный переключатель. Даже если у плагина нет
`config_schema()`, в карточке будет чекбокс «Включён для текущей кампании».

#### `config_schema() -> list[dict[str, Any]]`

Описывает поля настроек, по которым интерфейс автоматически строит виджеты.
Если метод не нужен, можно не переопределять его: базовый класс возвращает
пустой список.

Подробности — в разделе 3.

#### `process_row(row, config, campaign) -> dict[str, Any]`

Вызывается для каждой строки результата, пока плагин включён.

- `row` — словарь с извлечёнными полями одной страницы. В нём также есть
  служебные ключи `__url__` и `__status__`.
- `config` — настройки именно этого плагина из `campaign["plugins"][id]`.
- `campaign` — полный словарь кампании: поля, навигация, экспорт и т.д.

Плагин может:

- изменить существующее значение;
- добавить новую колонку;
- удалить ключ;
- вернуть тот же `row` или новый словарь.

Мутировать `row` на месте разрешено:

```python
row["Название"] = str(row.get("Название") or "").strip()
return row
```

Если вернуть `None`, изменения, сделанные в `row` на месте, всё равно
сохранятся. Но лучше всегда возвращать словарь.

### Важные правила безопасности

1. **Плагин вызывается из нескольких рабочих потоков.**
   Экземпляр плагина общий, а `process_row()` может выполняться одновременно
   для разных страниц. Не храните изменяемое состояние в `self`.
   Используйте локальные переменные, `config` и `row`. Если состояние
   действительно нужно, защищайте его блокировкой или используйте
   `threading.local()`.

2. **Исключения перехватываются.**
   Если `process_row()` выбросит исключение, ядро запишет предупреждение
   в лог и продолжит обработку следующими плагинами. Но это не sandbox:
   зависший плагин может заблокировать рабочий поток. Не делайте бесконечных
   циклов и долгих блокирующих операций без необходимости.

3. **Служебные ключи с `__` скрыты.**
   Ключи, начинающиеся с `__`, не показываются в таблице результатов и не
   попадают в XLSX/CSV. Не создавайте пользовательские колонки с таким
   префиксом. Внутренние ключи: `__url__`, `__status__`,
   `__plugins_applied__`.

4. **`config` и `campaign` лучше считать только для чтения.**
   Верхнеуровневый `config` передаётся как копия, поэтому изменения его
   ключей не сохранятся в кампанию. Вложенные объекты могут быть общими.
   Не изменяйте `campaign`.

5. **Списки склеиваются после цепочки.**
   Если нужен нестандартный разделитель, преобразуйте список в строку
   внутри своего плагина.

6. **Не добавляйте внешние зависимости без необходимости.**
   Плагин выполняется в том же процессе, что и приложение. Используйте
   стандартную библиотеку и уже установленные пакеты.

7. **Плагин работает построчно.**
   Отдельных хуков «до/после всей кампании» нет. Всё, что нужно для одной
   строки, должно быть доступно в `row`, `config` или `campaign`.

## 3. Автогенерация интерфейса настроек (`config_schema()`)

`config_schema()` возвращает список словарей. Каждый словарь описывает одно
поле настройки. Интерфейс сам создаёт виджет, подставляет значение и сохраняет
его в конфиг плагина. Пока плагин выключен, поля видны, но недоступны для
редактирования; их значения при этом сохраняются.

Пример:

```python
def config_schema(self) -> list[dict[str, Any]]:
    return [
        {
            "key": "prefix",
            "label": "Префикс",
            "type": "str",
            "default": "",
            "placeholder": "Например, NEW: ",
        },
        {
            "key": "markup_percent",
            "label": "Наценка, %",
            "type": "int",
            "default": 10,
            "min": 0,
            "max": 1000,
        },
        {
            "key": "currency",
            "label": "Валюта",
            "type": "choice",
            "default": "RUB",
            "options": [
                ("RUB", "₽ — рубли"),
                ("USD", "$ — доллары"),
            ],
        },
        {
            "key": "price_field",
            "label": "Поле с ценой",
            "type": "field_name",
            "default": "Цена",
            "allow_empty": False,
        },
    ]
```

### Параметры схемы

| Параметр | Обязательный | Тип | Описание |
|---|---:|---|---|
| `key` | да | `str` | Ключ в конфиге плагина. Пустые ключи пропускаются. |
| `label` | нет | `str` | Подпись поля. Если не указана, используется `key`. |
| `type` | нет | `str` | Тип виджета: `bool`, `str`, `int`, `choice`, `field_name`. По умолчанию `str`. Неизвестный тип пропускается. |
| `default` | нет | `Any` | Значение по умолчанию. Используется, если ключа нет в конфиге. |
| `placeholder` | нет | `str` | Подсказка внутри `QLineEdit` для типа `str`. |
| `min` | нет | `int` | Минимум для `int`. По умолчанию `0`. |
| `max` | нет | `int` | Максимум для `int`. По умолчанию `999999`. |
| `options` | нет | `list` | Варианты для `choice`: строки или пары `(value, label)`. |
| `allow_empty` | нет | `bool` | Для `field_name`: добавить пункт «Все / не выбрано» со значением `""`. |
| `tooltip` / `hint` | нет | `str` | Необязательная подсказка, показывается при наведении на подпись и виджет. |

### Типы полей

#### `bool`

```python
{"key": "enabled_extra", "label": "Дополнительная обработка", "type": "bool", "default": False}
```

Создаёт `QCheckBox`. В конфиг сохраняется `True` или `False`.

#### `str`

```python
{
    "key": "prefix",
    "label": "Префикс",
    "type": "str",
    "default": "",
    "placeholder": "Введите префикс",
}
```

Создаёт `QLineEdit`. Текст сохраняется как есть; обрезку пробелов лучше делать
в `process_row()`.

#### `int`

```python
{
    "key": "markup_percent",
    "label": "Наценка, %",
    "type": "int",
    "default": 10,
    "min": 0,
    "max": 1000,
}
```

Создаёт `QSpinBox`. Если `max < min`, значения меняются местами. Введённое
значение ограничивается диапазоном.

#### `choice`

```python
{
    "key": "currency",
    "label": "Валюта",
    "type": "choice",
    "default": "RUB",
    "options": [
        ("RUB", "₽ — рубли"),
        ("USD", "$ — доллары"),
        ("EUR", "€ — евро"),
    ],
}
```

Создаёт `QComboBox`. В конфиг сохраняется `value` из пары `(value, label)`,
а пользователь видит `label`. Можно передавать и просто строки:

```python
"options": ["RUB", "USD", "EUR"]
```

Если сохранённое значение отсутствует в текущем списке, интерфейс добавит его
как дополнительный пункт, чтобы не потерять настройку.

#### `field_name`

```python
{
    "key": "price_field",
    "label": "Поле с ценой",
    "type": "field_name",
    "default": "Цена",
    "allow_empty": True,
}
```

Создаёт редактируемый `QComboBox` со списком полей текущей кампании.
Пользователь может выбрать поле из списка или ввести своё имя вручную.

Если `allow_empty=True`, первым пунктом добавляется:

```text
Все / не выбрано  →  ""
```

Список полей обновляется при изменении набора полей кампании.

### Как это связано с `default_config()`

Рекомендуется указывать все ключи и в `default_config()`, и в
`config_schema()["default"]`:

```python
def default_config(self) -> dict[str, Any]:
    return {
        "enabled": False,
        "prefix": "",
    }

def config_schema(self) -> list[dict[str, Any]]:
    return [
        {"key": "prefix", "label": "Префикс", "type": "str", "default": ""},
    ]
```

`default_config()` задаёт базовый конфиг, а `default` в схеме страхует случай,
когда ключа нет в конфиге. Сохранённые в кампании значения всегда важнее
значений по умолчанию.

Если `config_schema()` вернёт пустой список или не будет переопределён,
карточка плагина останется минимальной: чекбокс включения, описание и путь
к файлу.

## 4. Готовые примеры плагинов

### Пример 1. Очистка текста без настроек

Плагин убирает HTML-теги и лишние пробелы во всех строковых полях. У него нет
`config_schema()`, поэтому в интерфейсе будет только чекбокс включения, описание
и путь к файлу.

```python
from __future__ import annotations

import html
import re
from typing import Any

from core.plugins.base import BasePlugin


class CleanTextPlugin(BasePlugin):
    id = "clean_text"
    name = "Очистка текста"
    description = "Убирает HTML-теги и лишние пробелы во всех строковых полях."
    order = 100

    def default_config(self) -> dict[str, Any]:
        return {"enabled": False}

    def process_row(
        self,
        row: dict[str, Any],
        config: dict[str, Any],
        campaign: dict[str, Any],
    ) -> dict[str, Any]:
        if not config.get("enabled"):
            return row

        for key, value in list(row.items()):
            if str(key).startswith("__") or not isinstance(value, str):
                continue

            text = re.sub(r"<[^>]+>", " ", value)
            text = html.unescape(text)
            row[key] = re.sub(r"\s+", " ", text).strip()

        return row
```

Что важно:

- плагин пропускает служебные ключи `__url__`, `__status__` и другие `__*`;
- списки не трогает — их склеит ядро после цепочки;
- `order = 100` означает, что он выполняется после `specs_parser` (`50`)
  и до `list_separator` (`200`).

### Пример 2. Очистка цены и наценка с настройками

Плагин:

- выбирает поле с ценой через `field_name`;
- очищает строку от валюты, пробелов и лишних символов;
- применяет наценку в процентах;
- форматирует результат в выбранной валюте.

```python
from __future__ import annotations

import re
from typing import Any

from core.plugins.base import BasePlugin

_CURRENCY_SYMBOLS = {"RUB": "₽", "USD": "$", "EUR": "€"}


class PriceMarkupPlugin(BasePlugin):
    id = "price_markup"
    name = "Наценка на цену"
    description = "Очищает цену от валюты, применяет наценку и форматирует результат."
    order = 100

    def default_config(self) -> dict[str, Any]:
        return {
            "enabled": False,
            "price_field": "Цена",
            "markup_percent": 10,
            "currency": "RUB",
        }

    def config_schema(self) -> list[dict[str, Any]]:
        return [
            {
                "key": "price_field",
                "label": "Поле с ценой",
                "type": "field_name",
                "default": "Цена",
            },
            {
                "key": "markup_percent",
                "label": "Наценка, %",
                "type": "int",
                "default": 10,
                "min": 0,
                "max": 1000,
            },
            {
                "key": "currency",
                "label": "Валюта результата",
                "type": "choice",
                "default": "RUB",
                "options": [
                    ("RUB", "₽ — рубли"),
                    ("USD", "$ — доллары"),
                    ("EUR", "€ — евро"),
                ],
            },
        ]

    @staticmethod
    def _parse_price(text: str) -> float | None:
        cleaned = re.sub(r"[^\d,.\-]", "", text)
        if not cleaned:
            return None

        # Если есть и точка, и запятая, десятичным считается последний
        # разделитель. Это покрывает форматы "1 234,56" и "1,234.56".
        if cleaned.rfind(",") > cleaned.rfind("."):
            cleaned = cleaned.replace(".", "").replace(",", ".")
        else:
            cleaned = cleaned.replace(",", "")

        try:
            return float(cleaned)
        except ValueError:
            return None

    def process_row(
        self,
        row: dict[str, Any],
        config: dict[str, Any],
        campaign: dict[str, Any],
    ) -> dict[str, Any]:
        if not config.get("enabled"):
            return row

        field = str(config.get("price_field") or "").strip()
        if not field:
            return row

        raw = row.get(field)
        if not isinstance(raw, (str, int, float)):
            return row

        price = self._parse_price(str(raw))
        if price is None:
            return row

        markup = float(config.get("markup_percent") or 0)
        value = price * (1 + markup / 100.0)
        symbol = _CURRENCY_SYMBOLS.get(str(config.get("currency") or "RUB"), "")

        row[field] = f"{value:.2f} {symbol}".strip()
        return row
```

Пример работы при наценке `10%` и валюте `RUB`:

```text
до:     "1 234,56 ₽"
после:  "1358.02 ₽"
```

Если поле пустое или цену не удалось разобрать, плагин оставляет строку без
изменений.

## 5. Готовый промпт для нейросети

Скопируйте блок ниже в ChatGPT, Claude или Gemini и замените описание задачи
в конце.

```text
Ты — Python-разработчик, пишешь плагин для настольного парсера FOSScol.

Контекст:
- Плагин — это файл .py, который кладётся в папку plugins/ проекта FOSScol.
- Класс плагина наследует core.plugins.base.BasePlugin.
- Атрибуты класса:
  - id: обязательный уникальный идентификатор в snake_case, например "my_plugin";
  - name: название для интерфейса;
  - description: короткое описание;
  - order: целое число, по умолчанию 100. Меньше — раньше.
- Метод default_config(self) -> dict[str, Any] возвращает настройки плагина.
  Всегда включай "enabled": False.
- Метод config_schema(self) -> list[dict[str, Any]] описывает поля настроек
  для автогенерации интерфейса. Поддерживаемые type:
  - "bool" -> QCheckBox;
  - "str" -> QLineEdit, поддерживает placeholder;
  - "int" -> QSpinBox, поддерживает min и max (по умолчанию 0..999999);
  - "choice" -> QComboBox, options — список строк или пар (value, label);
  - "field_name" -> редактируемый QComboBox с полями кампании,
    allow_empty=True добавляет пункт "Все / не выбрано" со значением "".
  У каждого поля обязателен key; label, default, placeholder, min, max,
  options и allow_empty — по необходимости.
- Метод process_row(self, row: dict[str, Any], config: dict[str, Any],
  campaign: dict[str, Any]) -> dict[str, Any] вызывается для каждой строки.
  row — одна строка результата, config — настройки плагина,
  campaign — полный словарь кампании. Можно менять row на месте и возвращать
  его или вернуть новый словарь.
- Плагин вызывается из нескольких рабочих потоков. Не храни изменяемое
  состояние в self; используй локальные переменные, config и row.
- Исключения внутри плагина перехватываются ядром, но лучше обрабатывать
  ожидаемые ошибки самостоятельно.
```
